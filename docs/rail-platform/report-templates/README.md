# 报告模板与生成规则

更新：2026-10-27。适用于主平台迁移 `045_report_templates.sql` 与 Presenton 新的 `template-plan` 接口。历史报告文件不重写。

## 使用流程

1. 在报告生成页选择项目上下文、报告类型和 Word / PPT 交付格式。
2. “格式模板”选择平台工程设计模板 v2，或上传不超过 20 MiB 的 `.docx` / `.pptx`。可从“模板管理”下载工程、合同编制参考、专利交底书、投标响应参考的起始文件，在 Office 中调整后上传。
3. 上传后确认可替换位置：报告标题、摘要、章节标题、正文、图片、图片说明或自定义字段。其余位置“保持原样”。普通成品文档没有占位符时，需要人工指定位置，不能假定系统已正确识别全部业务字段。
4. 保存规则后才可选择该模板。自定义字段出现在报告基本信息中，按用户填写原样替换；留空的字段不会由 AI 编造。
5. 填写章节、正文和配图，再选择“模板生成”或“AI 生成”。每章最多 20 张，最多 8 章 / 160 个图片位置，实际源图片总大小最多 100 MiB。报告图片仍要求为用户有权读取的已入库 PNG/JPEG；输出保存到目标项目。
6. 页面显示真实任务阶段、进度与失败原因，成功后提供下载。AI 内容仍需按原资料审阅；数字保留检查不能代替语义或专业审查。

## 模板作者约定

推荐用独立普通段落或文本框放置以下完整占位符。占位符可跨多个文字 run，但不要与固定正文混在同一个可替换块中。

| 占位符              | 用途                         |
| ------------------- | ---------------------------- |
| `{{title}}`         | 报告标题                     |
| `{{summary}}`       | 摘要                         |
| `{{section_title}}` | 章节标题                     |
| `{{section_body}}`  | 章节正文                     |
| `{{images}}`        | 配图位置，图片等比适配       |
| `{{caption}}`       | 图片说明的段落/文本框样式    |
| `{{party_a}}` 等    | 自定义字段，可在规则弹窗改名 |

- Word：保留原样式、页节、页眉页脚、编号和未替换内容。自动扩展时，章节标题至正文/图片/说明之间的连续正文块按章节克隆。全局标题、摘要、自定义字段应在该区域之外；循环区域不支持书签、批注或脚注引用，遇到这些结构需关闭自动扩展，分别指定章节位置。每章配置一个图片段落，该段落展开为所有图片与说明；正文自然分页。
- PPT：保留源母版、版式、主题、固定元素和图片位置。可预设纯正文、图文、单图和多图图册，纯正文及相同图槽数量的图文/图册各保留一个内容版式；每张内容版式均需章节标题。程序根据剩余正文和图片选择已声明的版式。长正文按原字号续页，图片只使用原模板指定区域，不随意改变字体、覆盖新设计或裁掉图片。
- 关闭自动扩展后，位置按“第几章”填写；固定 PPT 的容量不足时拒绝生成，不静默删掉多余图片或正文。
- PPT 标题、摘要、自定义字段、图片说明超出原框容量时明确报错。检测依据源字号、几何尺寸和行数估算；复杂字体度量仍需用实际 Office 渲染审阅。
- Word 设置打开时更新域；包含目录和交叉引用的模板仍需在 Word 中更新域并审阅，平台不宣称已重算所有 Office 域。
- 源字体名称原样保留。阅读端缺少字体会发生 Office 字体替代，应在模板设计与交付环境中安装合法可用字体。平台起始模板不是合同条款、专利结论或投标承诺的完整业务范本；应按真实项目和正式来源补全框架及内容。

## 支持边界

首期接受原生 DOCX/PPTX，旧 `.doc` / `.ppt` / `.dotx` / `.potx` 请先另存为对应文档格式。拒绝宏、ActiveX、嵌入可执行对象、路径穿越、DTD/实体声明及过大压缩包；解压上限 100 MiB、2000 个条目、单条目 30 MiB、500 个内容块。不会执行模板中的脚本，也不从模板关系下载远程资源。

可编辑对象是 Word 普通段落（包括普通表格单元格中的段落）和 PPT 原生文本框/图片。PPT 表格、SmartArt、图表等复杂对象按固定内容保留，不宣称可自动改写；需编辑的组合图形应先取消组合。Word 复杂域、内容控件、固定行高表格等不能作为可替换文本位置。源文件的复杂内部跳转、隐藏页、动画和非标准 Office 扩展不属于视觉一致性保证范围，导入前应整理为明确的可复用版式并预览。

Markdown 保留原文本生成链路，不应用 Office 模板字体和分页。已有外部 AI 二进制生成接口保留兼容；新 DOCX/PPTX 任务统一使用受控模板渲染。

## 实现与权限

- 主仓库 `apps/platform-api/utils/domain/capabilities/report/templates/`：ZIP/XML 解析、格式规则、模板仓库、版本快照、原生渲染及 AI 内容适配器。前端在 `views/platform/report-generation/`。
- 模板按项目权限管理，读操作要求项目可读，上传/确认/归档要求项目可写及任务写权限。普通项目成员不能越权读取其他项目模板。模板不自动出现在资产中心。
- 上传采用预签名直传；完成解析后保存 SHA-256 命名的独立原文件，尚未过期的上传 URL 无法改写已确认来源。配置修改使用 revision 乐观锁；任务在数据库中冻结来源摘要、对象键、规则及 revision。模板后续编辑或归档不改变已提交任务。
- 主平台的模板模式直接填入用户内容；AI 模式调用独立 Presenton 服务 `/api/v1/generate-file/template-plan`，只接收章节正文和图片顺序计划，再由同一主平台渲染器执行模板规则。主平台中没有模型调用代码或模型依赖；Presenton 不接管资产权限和最终模板存储。
- `REPORT_AI_API_URL` 继续指向原 `/api/v1/generate-file`，主平台自动追加 `/template-plan`，无需新增环境变量。平台与 Presenton 必须一起更新；旧 AI 服务不支持新接口时明确失败。
- AI 最多接收 8 张代表预览，每个模型请求最多 4 张，无预览图片保留输入顺序，完整说明和全部原图由主平台排版。长章节按约 600 字源片段顺序规划，避免超过当前本地模型上下文和输出预算。章节、每个图片位置和原文数字均需保留，不允许模型返回任意 XML/脚本/布局坐标。
