# 管理员 ComfyUI 模型管理

更新时间：2026-10-30。本功能管理推理工作流使用的模型文件；不管理 AI Toolkit 训练底模、vLLM 模型或生成的三维资产。入口：设计工作台 → 管理工具 → 模型管理，仅管理员可见。

## 使用流程

1. 在模型库查看 ComfyUI 当前节点报告的预置模型和管理员上传记录。预置挂载只读，服务不可达时显示原因，不把数据库“已入库”当作服务已识别。
2. 点击“上传模型”或现有模型的“上传新版本”，选择类别、名称、版本备注和文件；分片目录使用“选择目录”。单文件可以填写发布方提供的 SHA-256，留空时仍计算实际校验值。
3. 上传以 8 MiB 分片传输，可暂停；刷新或重新登录后，在“上传任务”重新选择全部原文件续传。客户端逐片核对已传内容，文件变化应新建上传。
4. 完成传输后由 Worker 校验长度、分片及整文件 SHA-256、支持格式和分片索引完整性，再原子入库。“已入库”与“服务已识别”分别展示。
5. 选择“用于工作流”，逐个勾选当前功能的工作流节点和新模型文件。系统只修改明确选择的模型输入，生成待验证版本，当前绑定保持原样。
6. 在更新计划点击“试运行”，进入已有应用工作区，用真实输入提交任务。候选版本和所选模型由后端锁定；正常的项目写权限、输入校验、Worker、结果登记和审计继续生效。
7. 当前管理员试运行成功且存在输出后才可“发布并切换”。发布时复核原绑定、候选版本及服务库存。后续新任务使用新版本，已提交任务保留原版本。

更新不是覆盖原文件；相同文件名的新上传也会生成独立快照。需要回退时在已有工作流管理中绑定保留的旧版本。已入库模型本轮不提供删除按钮，避免破坏历史任务和工作流引用；未入库或失败任务可取消并清理本次文件。

## 支持范围与限制

- 类别：扩散模型 `unet`、LoRA、VAE、文本编码器、Checkpoint、ControlNet、超分模型和 CLIP Vision。
- 文件后缀：`.safetensors`、`.gguf`、`.bin`、`.pt`、`.pth`、`.ckpt`；完整目录允许 `.json`、`.txt`、`.model` 配置。单次最多 256 个文件，单文件最大 128 GiB；整次总量受配置限制。
- 默认每次上传总量 128 GiB，不代表已实测 128 GiB 文件。磁盘须为在途分片和完整快照预留约双份空间及 512 MiB 余量。
- 禁止绝对路径、路径穿越、隐藏目录、反斜线、控制字符和符号链接。保存根目录由部署配置确定，浏览器不能指定系统任意路径。
- safetensors 校验头部及连续数据范围，GGUF 校验头部，JSON 校验语法，分片索引只允许引用本次目录中的文件。传统权重不在平台进程反序列化；格式校验不能证明模型兼容，最终以真实试运行成功为发布条件。模型文件应来自可信来源。
- 可替换的模型参数以已登记的节点输入名和 ComfyUI `/object_info` 实际可选项共同约束。自定义加载器未报告文件列表或输入名未纳入映射时不会强行替换；HF 目录上传成功也不表示所有自定义节点都能加载。
- 预置文件大小未从远程 ComfyUI 枚举时显示“—”，不伪造大小或哈希。不直接改写源 `models/checksums.sha256`，不下载权重、不自动安装自定义节点或依赖。

## 服务端与持久化

迁移 `046_managed_models.sql` 新增上传、分片、模型更新计划和试运行关联表。上传字节走 `PUT /api/v1/model-management/:id/parts/:file/:part`，每个请求都校验管理员身份与写权限；不通过浏览器直连 ComfyUI，不使用公开模型下载地址。

`MANAGED_MODELS_ROOT` 未设置时禁用上传入库；本地源码开发需为 API 和 Worker 配置同一可写绝对路径，并将该路径加入 ComfyUI 的额外模型路径。`MANAGED_MODELS_MAX_BYTES` 默认 `137438953472`，限制单次上传总大小。

整体 Compose 使用独立 `managed-models` 命名卷：平台以非 root 用户读写 `/app/managed-models`，ComfyUI 只读 `/managed-models`。`config/comfyui-managed-model-paths.yaml` 将分类映射到实际加载目录。文件最终位置是 `<根>/<类别>/platform/<模型 UUID>/<上传相对路径>`，工作流引用 `platform/<模型 UUID>/<相对路径>`。在途分片与校验暂存分别在 `.uploads`、`.staging`，不进入模型类别扫描目录。

并发分片按模型事务串行校验；后台通过租约认领，进程恢复可重新校验已原子提交的目录，不覆盖已入库快照。模型更新复用工作流版本和正常任务管线；普通绑定接口不能绕过未验证候选版本的发布检查。种子初始化保留已发布的管理员模型绑定。

审计记录模型创建、提交校验、取消、候选版本创建与发布；不记录权重字节。任何管理员均可查看全局模型库，但发布证明必须来自当前管理员的成功试运行。

## 部署、备份与恢复

本轮仅本地开发与验收，未生成交付包、未同步或部署服务器。后续发布必须按整体开发流程生成交付目录、测试、增量同步，再由用户授权执行部署。

发布时更新平台镜像、执行迁移 046，并更新 ComfyUI 的挂载和额外模型路径启动参数；模型服务程序本身无源码变更。独立平台单镜像/旧拆分 Compose 也保留模型卷，但外部 ComfyUI 仍须由运维映射同一存储，不能只给平台增加卷。

备份应同时保留 PostgreSQL 与 `managed-models` 卷，停止上传和校验后取一致快照，记录 SHA-256 并做恢复验证。`clean-project.py` 已把该卷纳入清理前备份清单；普通更新、停止容器不删卷。不要执行 `down -v` 或把模型卷当缓存清理。原始 `models/` 与管理员上传卷分别备份，不把运行期文件补进交付源码清单。

代码回退也须保留数据库迁移和模型卷；恢复旧备份应配套恢复两者。不能只恢复数据库而丢失其引用的模型快照。
