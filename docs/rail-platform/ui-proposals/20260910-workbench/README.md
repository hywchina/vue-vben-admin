# 设计工作台布局提案（2026-09-10）

本目录仅包含视觉与交互提案，不修改平台运行代码、API、数据库或路由。所有名称、数量、时间、状态及图片均为布局示例；图片复用仓库现有业务模式示意图，不是当前账号的生成成果。

## 1. 现有页面为何显乱

- “项目总数、项目资产、累计任务、运行任务”统计与每张项目卡中的数字重复，占据较多首屏空间。
- “平台管理与记录”是低频功能，却排在主要设计工作之前；普通设计用户更需要找任务和成果。
- 项目卡承担资料、成员、任务、资产、运行状态和操作入口等多项职责，每一层都用边框强调，难以一眼找到主要动作。
- 单项目场景仍使用宽大的卡片容器和分页栏，空白较多，但关键内容又分散。
- 如果直接再加五个同级大板块，信息总量会继续增加；应先合并重复概念。

## 2. 建议的信息层级

| 用户需要 | 推荐展示内容 | 层级与默认行为 |
| --- | --- | --- |
| 我的设计任务 | 名称、所属项目、最近更新时间、最近执行状态、继续设计/查看进度 | 主内容；以设计会话组织，展示最近一轮状态，避免每次重绘都重复一张大卡；独立训练/报告执行需回到各自页面 |
| 最近任务 | 最近更新的任务或会话，进行中状态清楚可见 | 作为上述主列表的默认排序/页签，不另建重复板块；可切换“进行中” |
| 我的项目资产 | 可访问项目名称、资产数量、更新时间、资产入口 | 项目与资产的快捷入口；首页只展示最近或置顶项目，完整管理进入二级视图 |
| 最近设计成果 | 缩略图/文件类型、名称、生成时间、保存状态、查看或继续深化 | 可包含未保存的任务输出；不能把这些输出直接视为已登记资产 |
| 最近保存资产 | 最近由当前用户执行保存/上传的资产、所属项目和保存时间 | A/C 与最近成果放在同一区域，用页签切换；按真实保存事件排序，不能用创建时间或生成时间冒充保存时间 |
| 管理与记录 | 用户权限、工作流管理、操作日志 | 页尾轻量入口；前两项仅管理员可见，日志仍遵守服务端数据范围 |

“我的任务”默认指当前账号发起的设计，不因管理员身份自动显示全平台任务。“我的项目资产”指当前账号可访问项目里的资产，资产可以由其他项目成员创建；页面文案与后端数据范围需明确区分。A/B 是可访问项目的跨项目概览，点击条目时先建立所属项目上下文；C 的正文只展示已选项目。

移除首屏四张大数字卡，数量放到相应模块标题或页签旁；首屏只保留“新建设计”一个主要操作，“新建项目”放到项目区域内。项目成员邀请、重命名、排序、归档、分页等保留在项目管理二级视图中，不因首页收敛而删除功能。

## 3. 三版方案

### A：日常工作总览（推荐）

- 上半区约 62% 为“我的设计任务”，38% 为“我的项目资产”；任务默认展示最近 3–5 条，项目默认展示最近或置顶 2–4 个。
- 下半区为成果图廊，“最近设计成果 / 最近保存资产”切换；每次展示 4–6 项，文件类型与保存状态清晰可见。
- 管理入口在页尾，不参与首屏视觉竞争。
- 优点：不切页就能找到当前工作、项目资产及最近成果，学习成本低。
- 取舍：首屏仍有三个区域，内容较多时需要限量，不能无限堆叠。
- 效果图：`workbench-a.png`。

### B：极简分页签

- 主内容使用“我的设计任务 / 我的项目资产”两个页签，顶部不展示全局统计卡。
- 任务页签：左侧是宽松任务列表，右侧用小缩略图展示最近成果，再用两条简洁文件记录展示最近保存资产。
- 资产页签：上方显示项目入口，下方显示已保存资产图廊。
- 优点：默认页面最清爽，任务和资产职责分明。
- 取舍：项目资产需要切换一次页签；右侧成果更适合快速识别，不能代替完整预览。
- 效果图：`workbench-b.png`、`workbench-b-assets.png`。

### C：项目工作空间

- 保留系统导航；内容区内左侧为紧凑项目列表，右侧展示选中项目。
- 项目名称、资产数、任务数、进行中数量使用一行轻量信息；正文上方为任务，下方为成果/保存资产切换。
- 优点：项目边界明确，不容易混用不同项目的素材；适合多项目并行且需要稳定上下文的用户。
- 取舍：增加一层项目导航；只有一个项目时，应把项目列表收敛为顶部项目标题，避免重复侧栏和无效留白。
- 效果图：`workbench-c.png`。

## 4. 与首页、资产中心的职责划分

- 首页：平台入口、全局概览与新设计引导。
- 设计工作台：当前用户的工作连续性——找回上次任务、继续设计、定位最近成果与项目。
- 资产中心：完整资产检索、目录、预览、上传和批量管理。
- 工作台不再复制完整首页指标，也不再把资产中心所有管理功能搬到首屏。

## 5. 后续实现边界

这些是待确认的界面方案，不代表新聚合接口已实现。确认样式后需要核对跨项目会话聚合、最近轮次状态、最近保存时间与操作者、已归档项目过滤等数据契约。不存在对应数据时应补后端查询或事件字段，不使用示例数据补齐运行页面。

未保存成果点击保存仍走现有显式确认；资产访问、项目切换、任务取消、成员管理和审计继续使用真实 API。空数据时模块内提供单一创建入口；加载失败只影响对应区域，并提供重试，不显示虚构统计。
