# 甲方 2026-08-20 修改意见评审与迭代范围

## 1. 评审依据

- 原始意见：`轨道交通客室智能快速设计工具模块说明20260820.docx`，共 23 页。
- 评审视角：终端设计师的操作效率、普通用户的理解成本、开发与部署的真实能力边界。
- 事实优先级：甲方本轮明确意见、当前代码与数据库迁移、真实工作流契约、自动化测试、已有项目文档。
- 实施原则：复用项目、设计会话、应用目录、任务、资产文件夹和 ComfyUI Worker；不新增静态假数据，不把未配置外部服务显示为成功。

## 2. 总体产品结构

本轮将平台组织为以下五个用户可理解的核心模块：

1. **设计工作台**：登录首页、项目与设计会话快捷入口、真实业务概览。
2. **设计生成**：同一个持久化设计会话内提供 CMF、客室零部件、客室效果三个业务上下文，并调用已有原子工作流。
3. **资产中心**：保存和检索图片、文本、文档、三维模型和模型文件；业务分类使用文件夹、标签、来源应用与任务血缘表达。
4. **任务中心**：记录工作流排队、运行、成功、失败、取消与结果确认，不伪造外部执行结果。
5. **平台管理**：管理员维护用户权限、工作流可见性与审计；普通用户只访问自身权限范围。

模型训练和报告生成仍属于外部能力。甲方文档没有确定训练服务协议、报告模板、结构化参数或 Word/PPT 技术路线，因此本轮只在首页明确显示“待接入”，不提供假提交按钮。

## 3. 逐项合理性结论

| 甲方意见 | 结论 | 设计、开发与用户侧处理 |
| --- | --- | --- |
| 首页提供六个快捷入口 | 调整后采纳 | 保留真实统计和最近工作内容，在首页增加快捷入口；“开始新设计”创建真实项目并进入设计会话，“查看我的设计”检索当前用户可访问项目中的真实会话。训练和报告入口明确标记待接入。 |
| 新建项目后进入设计对话 | 采纳 | 复用项目 API 与设计会话 API；项目仍是权限和数据隔离边界，会话是项目内的设计过程，二者不混为同一数据实体。 |
| 左侧平台导航 + 可折叠任务栏 | 采纳 | 设计页重新纳入平台固定外壳，继续保留项目会话栏并允许折叠，兼顾全局导航和设计画布宽度。 |
| 顶栏包含主题、通知、用户和头像 | 采纳 | 复用现有 `BasicLayout`、通知 API、用户资料与主题偏好，不另造一套顶栏状态。 |
| 平台名称改为“客运装备内装模块化分区快速设计平台” | 采纳 | 更新产品可见品牌文案；继续复用仓库内本地 Logo，避免外网图片依赖。 |
| 结果按多轮持续展示并可深化设计 | 采纳 | 复用持久化设计会话与任务时间线；用户点击“深化设计”时仍需把暂存结果确认登记为项目资产，再流转到兼容工作流。 |
| 多图网格、全屏查看、前后切换 | 采纳 | 多结果采用 2 张、3 张和 3 张以上的响应式网格；全屏查看器增加上一张、下一张和键盘切换。 |
| 输入器分为素材、文本、工具参数三层 | 采纳 | 当前统一输入器已经具备三层结构；本轮按业务上下文调整应用快捷顺序、提示词和素材入口显隐。 |
| 默认文生图，图生图时再显示上传入口 | 调整后采纳 | 默认工作流改为真实 `text-to-image`；仅当当前能力声明媒体字段时显示图片素材入口，文本工作流仍可从资产加载 Markdown。 |
| CMF、零部件、客室效果三套生成模块 | 调整后采纳 | 三者是设计语义上下文，不复制底层工作流。每个上下文提供不同提示词、模板和推荐工具顺序，底层继续调用同一批有版本、有任务和有血缘的原子能力。 |
| 结果下直接列出重绘、融合、放大、理解、多角度等操作 | 调整后采纳 | 使用“深化设计”列出与当前资产类型兼容且真实发布的工作流；不为同一操作维护第二套旁路执行逻辑。 |
| 下载时由用户选择本地路径 | 调整后采纳 | 浏览器下载位置受浏览器设置和权限控制；平台触发标准下载，不承诺所有浏览器都能弹出任意文件系统路径选择器。 |
| 保存资产时选择分类地址 | 采纳 | 保存任务暂存结果前选择当前项目的真实资产文件夹；API 校验文件夹归属，禁止跨项目保存。 |
| 资产不能跨板块或内容领域存储 | 不按物理隔离实现 | 硬隔离会破坏“资产是能力交换协议”的平台原则。使用项目边界、文件夹、标签、来源应用和任务血缘分类；跨项目访问仍由后端禁止。 |
| 提示词模板使用一级、二级菜单 | 采纳首批结构 | 先实现甲方已明确的颜色、材质、纹样、部件、视角和环境选项；后续清单可在不改变会话与任务协议的前提下扩展。 |
| 右下角文本多模态助手 | 采纳 | 复用现有按用户隔离的全局 AI 助手，并在设计页显示；助手失败时继续返回明确的未配置状态。 |
| 多视图生成三维模型 | 限定范围采纳 | 仅保留现有 `multiview-to-3d` 四视图到 GLB 工作流，并受适配器配置状态约束；不恢复旧的泛化“2D 生 3D”产品承诺。 |
| Word/PPT 报告生成 | 暂缓执行能力 | 等甲方确定模板、结构化字段、导出格式和技术路线后接入适配器；本轮不生成假文档。 |
| 参考 Liblib 实现模型训练 | 暂缓执行能力 | 参考截图不能替代训练服务 API、数据集规则、资源配额、版本发布和失败恢复协议；待接口与验收标准确定后实施。 |
| 其他设置与用户设置 | 不扩展 | 当前主题、通知、资料、头像和权限设置继续使用现有实现，遵循最小改动。 |

## 4. 本轮代码范围

### 4.1 首页与品牌

- 新增六项快捷入口和真实状态提示。
- 新建设计弹窗提交真实项目名称与任务说明，成功后进入设计会话。
- “我的设计”跨当前用户可访问项目读取真实会话并支持搜索、续接。
- 更新平台可见名称，不改认证、权限和项目范围。

### 4.2 设计会话

- 设计页使用平台外壳和全局 AI 助手。
- 会话栏可折叠，仍按当前项目和当前用户隔离。
- 新增 CMF、客室零部件、客室效果、报告生成的业务切换区；报告生成明确待接入。
- 三个可用业务上下文提供独立提示词、首批模板和推荐工作流顺序。
- 输入素材入口根据真实能力字段显示，不改变工作流参数快照和草稿持久化。

### 4.3 结果与资产

- 多图结果网格、全屏上一张/下一张浏览。
- “继续设计”统一改为用户语义更清晰的“深化设计”。
- 工作流暂存结果保存前选择当前项目资产文件夹；服务端校验文件夹与资产项目一致。

### 4.4 不在本轮范围

- 新训练服务、报告生成服务或第三方 API 接入。
- 新增文件类型或把 CMF、LoRA、报告改为文件类型。
- 修改 18 份原始 ComfyUI API JSON。
- 建立与项目资产协议平行的板块专用存储。
- 对未确定的高级参数、三维深化编辑和辅助设置进行推测性开发。

## 5. 验收重点

- 普通用户只能看到并续接自己的设计会话，所有项目和资产访问继续经过后端范围校验。
- 新建设计在刷新后仍存在，项目说明与会话历史不是前端内存数据。
- 未配置的训练、报告、AI 或 ComfyUI 能力显示明确状态，不产生成功任务或资产。
- 多图浏览、会话栏折叠、模块切换、提示词模板和资产文件夹选择在桌面与窄屏下可用。
- 保存生成结果不能指定其他项目的资产文件夹。
- 规范检查、类型检查、单元测试、真实集成、浏览器验收和生产构建按项目质量门禁执行。
