# 质量门禁与交付证据

## 1. 开发准入

功能进入开发前必须明确：需求编号、角色、数据范围、正常/失败路径、接口契约、数据库变更、审计事件和验收用例。外部服务还需明确超时、幂等、重试、回调鉴权和不可用时的表现。

## 2. 完成定义

1. 代码和迁移进入 Git，提交可定位业务目的。
2. 前后端不依赖假数据或只存在内存/本地的数据。
3. 后端强制身份、权限和资源范围，前端隐藏按钮不作为权限控制。
4. 校验失败、无权限、依赖失败和重试路径结果明确。
5. 写操作有事务或补偿策略，并记录不含敏感正文的审计事件。
6. 至少有单元测试；跨数据库、对象存储或权限边界必须进入集成验收。
7. 规范、类型、单元测试、集成测试和生产构建全部通过。
8. 需求状态、配置、运行方式和已知限制同步到交接文档。

## 3. 自动化门禁

| 层级 | 命令 | 证明内容 |
| --- | --- | --- |
| 静态规范 | `pnpm lint` | TypeScript/Vue/CSS 规范一致 |
| 类型边界 | `pnpm typecheck:rail` | API 与目标 Web 类型可编译 |
| 单元/状态 | `pnpm test:rail` | 密码、角色、审计、资产、AI、配置和 Web 状态 |
| 真实集成 | `pnpm test:rail:integration` | PostgreSQL、MinIO、三账号、项目/会话/日志隔离和文件上传 |
| 可部署产物 | `pnpm build:rail` | Nitro 服务端与生产 Web 均能构建 |

`.github/workflows/rail-platform-ci.yml` 在推送和合并请求执行门禁，集成任务自行启动依赖，失败时输出诊断。

## 4. 测试分层

- **单元测试**：纯函数、校验、权限范围、状态和外部响应解析。
- **集成测试**：真实 API、PostgreSQL、MinIO 与用户隔离；唯一标识，只清理本次数据。
- **浏览器验收**：登录、表单、上传预览、弹窗和响应式；当前有人工证据，P1 固化为 Playwright。
- **非功能测试**：备份恢复、负载、稳定性、故障注入和兼容性；试运行前完成。

当前不虚设覆盖率数字。P1 先生成基线，再按高风险模块设置分支覆盖门槛，不能用无意义断言追求百分比。

## 5. 发布阻断条件

- 已知身份绕过、跨用户/跨项目读取、明文密钥或敏感正文进入日志。
- 迁移无法在生产副本完成，或没有经过恢复验证的可用备份。
- P0 未完成、自动化门禁或生产构建失败。
- ready 不能正确反映数据库/对象存储故障。
- 外部适配器未配置却展示成功。

发布记录必须包含 Git 提交、迁移版本、配置清单、测试结果、已知限制、恢复方式和批准人。
