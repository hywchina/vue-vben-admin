# 质量门禁与交付证据

## 1. 开发准入

功能进入开发前必须明确：需求编号、角色、数据范围、正常/失败路径、接口契约、数据库变更、审计事件和验收用例。外部服务还需明确超时、幂等、重试、回调鉴权和不可用时的表现。

## 2. 完成定义

1. 代码和迁移进入 Git，提交可定位业务目的。
2. 前后端不依赖假数据或只存在内存/本地的数据。
3. 后端强制身份、权限和资源范围，前端隐藏按钮不作为权限控制。
4. 校验失败、无权限、依赖失败和重试路径结果明确。
5. 写操作有事务或补偿策略，并记录不含敏感正文的审计事件。
6. 至少有单元测试；跨数据库、对象存储或权限边界必须进入集成验收。
7. 规范、类型、单元测试、集成测试和生产构建全部通过。
8. 需求状态、配置、运行方式和已知限制同步到交接文档。

## 4. 测试分层

- **单元测试**：纯函数、校验、权限范围、状态和外部响应解析。
- **集成测试**：真实 API、PostgreSQL、MinIO 与用户隔离；唯一标识，只清理本次数据。
- **浏览器验收**：登录、表单、上传预览、弹窗和响应式；当前有人工证据，P1 固化为 Playwright。
- **非功能测试**：备份恢复、负载、稳定性、故障注入和兼容性；试运行前完成。

当前不虚设覆盖率数字。P1 先生成基线，再按高风险模块设置分支覆盖门槛，不能用无意义断言追求百分比。

## 5. 发布阻断条件

- 已知身份绕过、跨用户/跨项目读取、明文密钥或敏感正文进入日志。
- 迁移无法在生产副本完成，或没有经过恢复验证的可用备份。
- P0 未完成、自动化门禁或生产构建失败。
- ready 不能正确反映数据库/对象存储故障。
- 外部适配器未配置却展示成功。

发布记录必须包含 Git 提交、迁移版本、配置清单、测试结果、已知限制、恢复方式和批准人。

## ComfyUI 工作流发布门禁（2026-08-08）

- 工作流 API JSON、参数节点、输入字段和输出节点必须在登记时完成结构校验。
- 18 份工作流的每个非连线输入必须由公开参数或媒体输入映射覆盖；更新 ComfyUI 节点后需基于真实 `/object_info` 重生成并运行完整性测试。
- 用户能力接口不得返回节点编号、原始工作流、外部地址或服务端令牌。
- 任务必须固定 `workflow_version_id`，切换绑定后历史和运行中任务不得漂移。
- 必须验证页面关闭后继续、Worker 重启租约恢复、幂等输出回执、取消、超时和连续轮询失败。
- 必须使用临时模拟 ComfyUI 验证 `/prompt`、`/history`、`/queue`、`/view` 和取消协议。
- 发布到真实环境前必须补做真实 ComfyUI、真实模型、MinIO 资产预览和 GPU 长任务验收；本机模拟测试不能替代该门禁。
- `ADAPTER_NOT_CONFIGURED`、外部执行失败或输出登记失败时不得产生成功任务或占位资产。
- 暂存输出不得自动进入资产中心或被任务当作输入；跨工作流流转必须校验已登记资产、当前项目、当前用户、目标应用与具体输入位。
- 设计草稿必须按当前用户、项目、设计会话和应用隔离；恢复资产时重新校验会话归属、登记状态、项目范围、输入位和类型，不能信任浏览器缓存。
- 同一设计会话只允许一个 `queued`、`running` 或 `cancelling` 任务，不同会话可并行；必须由后端事务互斥保证，不能只依赖按钮禁用。
- 普通用户的跨应用复用只能发生在当前设计会话内，用户仍须明确确认暂存输出加入项目资产；管理员旧实例流转仅作为单功能调试兼容链路。
- 多轮工作区必须从任务台账恢复参数、有序输入和输出；带图片对比节点的能力只能从服务端工作流快照只读推断，不能修改原始 API JSON 或依赖浏览器静态名单。
- 分区任务必须保持 `job_inputs.asset_id` 为 Worker 消费的原图，并通过独立标记快照恢复用户输入；输出对比左图必须是标记前原图，不能使用标记图或其他轮次图片冒充。
- 设计会话任务必须持久化提交时的 `design_mode`；共享应用不能根据当前页面模式或应用 key 猜测历史轮次语义。零部件、CMF 和客室效果历史图片结果刷新后仍须分别恢复各自固定操作及顺序。
- 三种视觉模式的提示词模板必须从平台 API 读取，普通用户只读、具备 `platform:application:write` 权限的管理员可维护；分类与选项顺序、重复标识、空分类和审计摘要均须验收，审计不得记录完整模板正文。环境更改只能展示客室效果目录中的“光环境”和“窗外环境”分类。
- 提示词选择必须完整显示全部已选标签并支持逐项删除；历史输入图片主体点击只能打开普通图片预览，右下角遮罩按钮默认隐藏、悬浮或键盘聚焦时显示，点击后才进入遮罩编辑器。
- 零部件首屏工具顺序必须为“文生图、局部重绘、标记修改、多图融合、多角度生成、三维生成、图像放大、图片理解、提示词模板、更多”；客室效果必须为“文生图、标记生成、局部重绘、部件/材质融合、平面图填色、环境更改、图像放大、图像理解、提示词模板、更多”。不可用契约必须禁用并明确提示，不能伪造成功。
- 零部件与客室效果图片结果操作必须根据任务持久化模式显示，顺序与产品需求一致；多角度直提交流程只能消费一张来源图，三维直提交流程必须完整提供前、左、后、右四视图。
- 图片理解和局部重绘只把当前图片带入对应编辑流程，不得因点击结果操作立即创建任务；图像放大只有在用户确认倍率后提交，多图融合的编辑框和弹窗两种路径都必须复用当前项目资产、真实输入契约和会话任务互斥。
- 需要图片输入的能力必须显示与工作流槽位一致的图片托盘，支持本地与资产中心多选、删除和左右排序；固定 N 张时，少于 N 张必须显示剩余数量并阻止提交，超过 N 张必须只保留前 N 张并明确提示。托盘图片主体点击进入遮罩编辑；历史输入图片仍保持主体放大、悬浮按钮进入遮罩的既有分工。
- 文本工作流输出必须以 `.md` 和 `text/markdown` 登记；浏览器验收需验证 Markdown 排版、复制原文、输入悬浮操作、完整参数弹窗，以及结果图标的可访问名称和悬浮说明。
- 参数 Schema 变更后开发 Worker 必须自动重载；协议不兼容错误不得向页面泄露内部 Zod 校验结构。
- 资产预览必须验证对象内容、文本内容和跨项目拒绝，不能只校验前端弹窗。

## AI Toolkit LoRA 发布门禁（2026-08-25）

- 浏览器不得获得 `LORA_API_TOKEN`、训练服务器绝对路径或完整 `job_config`；模型、VAE、数据集根目录和 GPU ID 只能由平台后端映射。
- 创建训练必须校验当前项目写权限、图片已入库、对象版本可用、图片不重复、逐图 caption 非空、数据集总容量和总步数范围。
- 必须同时调用 AI Toolkit 任务入队和 GPU 队列启动接口；只完成其中一步不能宣称训练已开始。
- Worker 重启或外部请求结果丢失时必须按平台任务业务 ID 查询外部 `job_ref`，不得重复创建训练；产物登记必须通过 `lora_artifact_receipts` 幂等。
- 取消必须由 Worker 调用外部停止接口；完成与取消并发时不得丢失已经完成的模型产物。
- `.safetensors` 必须先下载到平台后端、校验大小并写入私有对象存储，再登记为当前项目 `model` 资产和 `job_outputs`；不得把 AI Toolkit 未鉴权的 `/api/files` 地址返回浏览器。
- 单元测试需覆盖受控模板与 AI Toolkit 协议；发布到真实环境前必须用已验证权重和数据集完成一次 smoke 训练，并核对日志、Loss、停止、模型下载、MinIO 入库和跨项目拒绝。

## 报告生成发布门禁（2026-08-25）

- 创建报告必须校验当前项目写权限、图片已登记、对象版本可用、PNG/JPEG MIME、章节/图片数量和总输入容量；通用任务接口不得绕过受控报告接口。
- 浏览器只能提交项目资产 ID 和白名单报告结构，不得提交对象键、服务端路径、任意模板代码或存储地址。
- 输出必须先写入私有对象存储，再在事务中登记同项目 `document` 资产、版本、标签和 `job_outputs`；数据库失败时必须补偿删除对象。
- 输出资产 ID 和对象键在任务创建时预分配，Worker 租约恢复和最多 3 次重试不得产生重复资产。
- 取消必须由报告 Worker 确认；渲染完成与取消并发时，取消任务不得登记输出资产。
- 单元测试需同时生成 DOCX/PPTX/Markdown；样例 DOCX 必须逐页渲染检查，样例 PPTX 必须逐页渲染检查并通过越界检测，Markdown 必须校验 UTF-8 结构和自包含图片；浏览器需验证三种格式、两种生成方式、下载入口和 390px 无横向溢出。
- AI 方式必须由后端以真实 multipart 图片文件调用已配置服务，校验上游状态、超时、输出大小，以及 OOXML 签名或 UTF-8 Markdown 内容；未配置时返回 `ADAPTER_NOT_CONFIGURED`，不得回退为模板结果伪装 AI 成功。
- 模板与 AI 任务必须持久化 `generation_mode`，任务列表、审计和输出资产元数据可区分生成方式；两条路径各至少完成一次真实任务与下载验收。
