# 产品需求与验收基线

> 文档版本：1.0；基线日期：2026-08-04状态：平台框架基线；外部 AI/工作流执行服务不在本阶段实现范围内

## 1. 产品目标

本产品是轨道交通客室智能设计的统一工作平台，不是单页演示或多个外部 API 的简单拼接。平台负责长期稳定的用户、权限、项目、资产、任务、通知、审计和个人 AI 会话；ComfyUI、大模型、LoRA 训练和报告生成等计算能力通过有版本的适配器契约接入。

成功标准是：用户能在受控项目上下文中完成输入资产登记、应用调用、任务追踪和输出资产沉淀；数据在刷新、重启和跨用户场景下仍正确，权限由后端强制执行，关键行为可审计，部署和故障恢复可以复现。

## 2. 用户与职责

| 角色 | 主要职责 | 强制边界 |
| --- | --- | --- |
| `admin` | 用户与角色管理、全局项目可见、全局日志查看 | 不能在个人资料页修改角色；不能停用或降级最后一名启用管理员 |
| `user` | 在参与的项目中管理资产、任务、应用和个人日志/AI 对话 | 不能管理角色或读取其他用户的日志、项目和 AI 对话 |

平台角色只有 `admin` 和 `user`；项目内另有 `owner`、`editor`、`viewer`。两层授权解决的问题不同，不能相互替代。

## 3. 核心领域关系

1. **项目**是协作、授权和数据隔离上下文。
2. **资产**是可追溯、可复用、可版本化的多模态输入与输出。
3. **应用**是外部能力目录与契约，不直接拥有用户数据。
4. **任务**记录应用在项目中消费的资产、参数、状态和输出。
5. **设计会话**属于当前用户和项目，可按轮次组合多个应用；应用不直接拥有用户会话。
6. **AI 对话**属于个人数据，可关联项目和附件，但不会自动成为项目公共资产。
7. **审计事件**记录请求和关键业务动作，不记录密码、令牌、聊天正文或文件内容。

## 2026-09-10：三维资产下载格式与系统工具栏

三维查看器的导出区按 GLB、OBJ、STL、FBX 顺序同时展示四种格式入口，并保留原文件下载。转换基于经过受控预览接口读取的当前模型，不把查看器灯光、网格与摄影机写入下载文件。GLB 支持材质；OBJ、STL、FBX 为静态网格转换，不承诺保留完整材质、动画或骨骼。FBX 使用 7.4 ASCII，保留几何、法线、UV 和世界变换；骨骼、实例及活动形变模型明确提示下载原文件，不生成伪成功文件。目标桌面建模软件的 ASCII FBX 兼容性需单独验收。

系统顶部工具栏移除全屏入口，并在应用启动时覆盖旧全屏偏好；图片和三维查看器自己的放大/全屏功能保持原行为。

### 比例与模板尺寸联动（2026-09-10）

- 设计输入器采用 A 版比例宫格：自动、9:16、2:3、3:4、1:1、4:3、3:2、16:9，合并原宽高快捷入口。锁定比例时修改任一边联动另一边，解锁后可独立编辑。自动恢复工作流默认宽高。
- 始终遵守当前工作流范围与步长；比例联动选择最近的兼容尺寸并提示调整，无法满足比例时阻止变更。
- 模板维护可配置比例或完整宽高；应用模板同时更新外部实际参数和会话草稿。仅配置比例时以当前宽度为基准联动，完整宽高必须合法，比例与宽高冲突时阻止应用。只应用尺寸不清空已有提示词。
