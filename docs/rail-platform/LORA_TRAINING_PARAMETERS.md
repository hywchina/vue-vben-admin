# LoRA 训练参数：普通 demo 与平台页面

## 配置基准

当前基准是 AI Toolkit 的 `config/flux2_klein_9b_interior_lora.yaml`，用于 Flux2 Klein 9B 室内风格 LoRA。不是 20 步 smoke 配置，也不是 AI Toolkit 通用 UI 的默认 jobConfig。页面仅呈现这份普通 demo 的 72 项叶子参数；容器、列表本身不作为独立参数，空过滤列表与分辨率列表作为整体呈现。

`apps/platform-api/utils/domain/capabilities/lora/demo.ts` 保存无凭据的基准、字段映射和中文说明，由平台 Web 与配置生成器共享。`fixtures/ordinary-demo.json` 是 2026-10-08 从普通 YAML 解析的测试快照，仅把数据集绝对路径替换为占位符；以后更新 demo 时须同步快照、目录及对应测试，不能只改一端。

## 主面板：常用项

| 页面参数 | YAML 字段（省略 `config.process[0].`） | 默认与限制 |
| --- | --- | --- |
| 使用底模 | `model.name_or_path` | Flux2 Klein 9B；从服务端白名单选择，不接收实际路径 |
| 训练步数 | `train.steps` | 1500；20–10000 的整数 |
| 单张图片重复次数（Repeat） | `datasets[0].num_repeats` | 1；1–100 的整数 |
| 触发词 | `trigger_word` | interiorstyle；2–64 字符，英文开头，可含数字、下划线及连字符 |
| 训练图片分辨率 | `datasets[0].resolution` | 512；可选 512/768/1024，并同步样图宽高 |
| 模型效果预览提示词 | `sample.samples[0].prompt` | `[trigger], modern style interior design`；最多 1000 字符 |

任务名称、项目图片选择/上传、逐图 caption、提交检查及任务历史是平台业务信息，不是额外训练超参数，继续保留。任务名称不同于服务器内部 `config.name`，后者由任务 UUID 生成。

不再提供 Epoch，也不再以“图片数 × Repeat × Epoch”计算步数。`steps` 是直接设定的优化更新总数；修改图片数量和 Repeat 不改变这个总数。推荐值以普通 demo 为起点，不代表对所有数据、显卡或风格的最优保证。

### 有意保留的运行时差异

- 普通 demo `logging.use_ui_logger=false`；平台固定为 `true`，支撑 Loss 曲线，问号中明确解释差异。
- 模型、VAE、数据集路径来自后端配置；内部任务名按任务 ID 隔离，不使用 demo 的固定目录名。
- Rank 和 Alpha 联动；样图宽高跟随训练分辨率，不单独修改。
- 默认 `disable_sampling=true` 与普通 demo 一致，默认不生成训练中实时样图。用户在专业设置关闭“禁用训练样图”后才每 250 步采样一次；预览提示词不会在关闭采样时产生图片。
- 新任务保存及样图间隔固定为 demo 的 250，不再按总步数动态缩短。

## API、安全及旧任务

### 数据集数量与分批传输（2026-10-08）

- 不再固定限制每个训练任务最多 100 张图片；选图计数显示“已选 N 张”，本地多选上传不按 100 张截断。仍要求至少 1 张、图片不重复、逐图 caption 非空、当前项目写权限及已登记的可用图片版本。
- 保留 `LORA_MAX_DATASET_BYTES` 总容量保护，默认 2147483648 字节（2 GiB），按已登记图片文件字节合计校验，不是图片张数限制；Worker 在读取前再次检查，并核对读取字节数与登记版本一致。
- Worker 逐批读取并向同一个受控数据集目录发送图片及同名 `.txt`，每批最多 16 张、图片和标注合计目标 32 MiB；一张图片超过目标时独立传输，仍受单文件上传与数据集总容量规则约束。这是传输批次大小，不是新的数据集总张数上限，也不是新增 demo 参数，因此不在训练参数表单中展示。
- 上一批成功后才读取下一批，全部上传回执完整后才创建训练任务并启动 GPU 队列。不把整个数据集的图片常驻内存；单张仍完整读取，multipart/Blob 也可能复制当前批次，不能将 32 MiB 宣称为进程内存硬上限。
- 传输期间续租并在操作之间检查取消请求；上传失败沿用既有重试策略，对同一任务目录以确定性文件名覆盖重传，不重复追加文件。当前不是断点续传：重试从首批开始。部分上传目录不会自动删除，以免破坏既有数据；正式运行需按运维策略处理失败任务残留目录。

新请求 `/api/v1/lora/trainings` 必须提供 `parameters.steps`；不接受 Epoch 作为替代。仅解析底模、步数、Repeat、触发词、分辨率、提示词、Rank、学习率和采样开关，额外字段会被白名单剥离。项目写权限、逐图 caption、图片重复/归属/版本、容量与外部服务未配置检查不变。

数据库中已有的排队任务仍兼容旧 `epochs`：只有缺少 `steps` 且存在 `epochs` 的历史任务使用原公式、原 checkpoint 间隔及默认启用采样行为。历史参数不改写，无新迁移或环境变量。正式环境须一起更新 Web、API 与 Worker（或重建系统镜像），不能只替换页面。

验证不要求创建真实 GPU 任务：纯函数检查完整字段集合和安全快照，API Schema 检查范围/非法字段，组件测试检查可见项、逐图描述、提交载荷和失败禁用。真实浏览器检查问号、7 类分组、联动和 390px 窄屏。训练服务不可达时，不宣称已验证真实训练质量或模型产出。
