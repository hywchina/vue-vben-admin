# 平台单镜像实施计划

## 范围

以当前 vue-vben-admin 功能分支为代码基线，将 Web、API 和独立任务 Worker 打包为一个业务镜像。PostgreSQL、MinIO、开发邮件沙箱使用上游镜像，由 Compose 管理；ComfyUI、AI Toolkit、vLLM 和 Presenton 保持独立服务。本项目不直接加载模型，无需 CUDA 镜像或 GPU 设备挂载。

## 顺序与验收

1. 核对实际服务、108 个 REST 路由、已有集成测试和当前分支。原有未提交的训练模型相对路径改动保留，单独核对后提交，不混入容器改造。
2. 当前平台服务停止，启动独立 PostgreSQL/MinIO/Mailpit 测试环境，使用新命名卷，不修改旧数据。运行本地源码 API 的真实集成测试，覆盖认证、项目、资产、权限隔离、会话和任务；真实 GPU 调用逐个执行。
3. 梳理外部依赖状态。ComfyUI 使用上一轮已验证的服务；其他服务能实际完成的链路记录成功，未启动或不可用的链路必须记录为未验收，不以模拟或预检代替真实推理。
4. 本地 API 验证通过后编写项目内 Dockerfile、进程管理、健康检查、配置模板和 Compose。镜像包含构建产物、Worker、迁移及种子工具；排除模型、业务数据、密钥、本机依赖及开发文档素材。
5. 构建一个业务镜像，创建容器，从宿主通过发布端口重复集成验收，验证真实对象上传、报告产物、Worker 和外部能力。验证 Web 静态资源及浏览器访问，不改页面布局。
6. 执行规范、类型、单元测试及生产构建门禁；记录实际失败和处理结果。导出镜像及校验清单，独立英文 Conventional Commits 配合中文 commitlog，推送确认的分支。

## 提交划分

- 计划与隔离测试环境。
- 模型路径可移植性（既有改动单独核对）。
- API 验证工具与测试中发现的独立修复。
- 平台单镜像构建与配置化启动。
- 验收记录、离线交付说明和部署文档同步。

原有用户数据库、对象、账号和外部容器不清空；不执行 down -v。新测试数据使用唯一标识，测试清理仅针对本轮创建的数据。模拟协议测试、真实服务测试与暂未验证的功能分别记录。
