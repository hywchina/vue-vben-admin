## 2. 原始需求整理

### 2.1 首页

- 登录后页面统一称为“首页”，不再称“设计工作台”。
- 首页以欢迎文案为中心，下方保持 3×2 六个快捷入口：开始新设计、查看我的设计、查看资产中心、开始模型训练、开始报告生成、设计工作台。
- 页面布局按 0820 示意图执行，颜色不照搬示意图中的绿、黄标注色，必须使用现有平台主题。

### 2.2 设计工作区总体骨架

- 保留用于切换大功能模块的平台功能侧栏。
- 在平台侧栏右侧提供可单独收起、展开的任务栏，用于项目选择、新建会话、搜索和历史会话。
- 顶部保留 Logo/平台导航及用户中心、设置等平台功能。
- 主区域用于连续展示生成结果；底部固定内容编辑器和业务模式切换区。
- 业务模式包括客室零部件生成、CMF生成、客室效果生成和报告生成。

### 2.3 输入编辑与能力工具

- 输入区由素材、提示词、快捷工具、生成参数和发送按钮组成。
- 常用工具顺序按文档收敛为：文本、文生图、理解、重绘、扩图、多图、放大、更多。
- 文生图默认不要求上传图片；单图编辑类能力使用单图；多图融合类能力才使用多图输入。实际输入数量仍由后端能力 Schema 决定。
- 高级能力和后续同类版本不应继续在页面硬编码，应通过可扩展目录和真实能力契约接入。

### 2.4 结果与连续设计

- 一个设计会话按轮次连续展示输入、执行状态和结果。
- 多图片结果按 2 张、3 张、4 张以上使用不同网格；图片可进入全屏查看并前后切换。
- 结果继续支持下载、保存到项目资产、重新运行、局部编辑和“深化设计”。
- 外部能力输出只有登记为当前项目资产后才能被其他能力复用。

### 2.5 专项模块

- 报告生成按结构化区段组织下拉选择、文本输入、图片素材和 Word/PPT 交付格式。
- 模型训练参考 Liblib 类界面，包含 Repeat、Epoch、触发词、效果预览提示词、图片打标/裁剪和训练选项。
- 文档提到提示词模板的两级框架，但具体分类、词库和持久化规则尚未给出最终内容。

## 3. 已完成开发

### 3.1 原始材料与可追溯基线

- 原样保存需求 DOCX，并直接提取其中的 22 张 PNG 和 1 个 WDP 资源。
- 源文件与仓库副本 SHA-256 一致；`original/` 在基线提交后没有修改。
- 建立独立中文 `COMMITLOG.md`，逐条说明每个英文提交的动机、范围、真实性边界和验证情况。

### 3.2 首页

- `/home`、菜单和页签统一命名为“首页”。
- 删除旧首页闭环图、趋势图、统计卡片、最近项目和成果看板，使首页只承担门户职责。
- 欢迎区和六个入口按 3×2 排列，颜色使用平台红、浅红、雾灰和灰色边界。
- 新设计使用真实项目创建 API；历史设计使用真实最近会话；资产和项目入口使用真实路由。
- 训练和报告缺少契约时保持可点击说明，不伪造任务或结果。

### 3.3 设计工作区

- `/design` 重新复用平台基础布局，形成“平台功能侧栏 + 顶部栏 + 独立任务栏 + 结果/输入区”的两级侧栏骨架。
- 任务栏支持项目选择、新建会话、搜索、历史会话、重命名、软删除和收起/展开。
- 任务栏收起只释放任务栏宽度，平台侧栏和顶部栏始终保留。
- 移除页面内部重复的 Logo、用户卡片和会话标题栏；修复双侧栏下结果区、欢迎区和输入器横向溢出。
- 输入器、草稿、会话互斥、资产输入、遮罩/分区标记、任务提交和审计继续使用原有真实链路。

### 3.4 可扩展业务模式与工具顺序

- 新增 `design-modes.ts`，集中管理四种业务模式、说明、占位文案和有序应用键。
- 页面只展示平台 API 返回的 `visible=true` 且存在 `capabilityCode` 的能力。
- 客室零部件、CMF和客室效果三种视觉模式的前七项统一为文本、文生图、理解、重绘、扩图、多图、放大，其余能力进入“更多”。
- 后续接入同类型组件或多版本能力时，优先扩展目录和后端契约，不复制页面逻辑。

### 3.5 结果展示

- 共享结果卡片支持 2/3/4+ 图片布局和 `+N` 聚合。
- 共享全屏图片查看器支持上一张、下一张及键盘左右方向键。
- 保留缩放、拖拽、遮罩对比、3D、下载、保存、重跑和深化设计能力。
- 面向用户的结果文案使用“能力版本”和“深化设计”，不暴露底层工作流名称。

### 3.6 报告与训练的前端待接入布局

- 报告弹窗已经呈现报告类型、Word/PPT、标题说明、三项图片素材和补充说明。
- 模型训练弹窗已经呈现 Repeat、Epoch、触发词、预览提示词、图片打标/裁剪、裁剪方式、裁剪尺寸和打标模型。
- 两者当前均为禁用布局；没有能力契约和外部服务时不能提交，不创建静态任务或假结果。

### 3.7 品牌和交互修复

- 平台名称统一为“客运装备内装模块化分区快速设计平台”。
- 启动时只同步名称和版权身份字段，不清除用户保存的主题与布局偏好。
- 待接入入口不再使用会阻断解释操作的 `aria-disabled`，仍可点击查看原因，但不会改变模式或创建任务。

## 7. 开发过程中发现的问题

### 7.1 已修复

- 原设计路由使用 `noBasicLayout` 脱离平台壳层，与项目“固定平台外壳”和甲方两级侧栏布局冲突；已恢复平台基础布局。
- 原首页承载闭环图、统计和大量看板信息，与甲方要求的纯门户页冲突；已收敛。
- 浏览器验收仍假设单页平铺至少 18 项应用、设计页必须从 `(0,0)` 全屏显示、输入器必须低于 330px；这些断言与四模式和两级侧栏新结构冲突，已更新。
- 旧浏览器偏好可能恢复旧平台名称；已只同步发布身份字段。
- `aria-disabled` 会使“待接入”入口无法通过语义化操作查看原因；已改为只读状态标记。
- 双侧栏加入后，Grid 子项默认最小宽度导致结果区和输入器在窄视口横向溢出；已补充 `min-width` 和盒模型约束。

### 7.2 尚未解决或需要外部条件

- 本地实际 API 没有配置 ComfyUI，真实任务会按正确规则返回 `ADAPTER_NOT_CONFIGURED`；全量浏览器脚本因此无法完成后续成功结果链路。
- 浏览器验收当前依赖外部适配器配置，尚未自动启动一个与 Web/API 生命周期一致的临时模拟服务；建议后续将“无适配器失败验收”和“配置模拟适配器的成功验收”拆成两个明确场景。
- 报告生成和 LoRA 训练只有需求参考，没有稳定后端契约、数据协议和部署服务。
- 需求文档中仍存在空编号、黄色待确认段落和未定提示词词库，不能据此宣称业务细节已完成。
- 当前没有甲方提供的独立授权中车 PNG/SVG 标识文件。
- 当前没有可复用的真实多图片成功输出会话，尚未以真实推理结果完成多图视觉签收。
- 仓库中 `apps/web-antd/src/modules/platform/data.ts` 仍是早期样例常量遗留，后续开发不得重新把它作为运行时业务数据源。

### 7.3 本轮自身的纠偏记录

第一版曾把 0820 工作区图错误理解为功能分区示意，只增加了一个全屏历史栏，没有严格保留平台功能侧栏和顶部栏。该偏差已在 `b491ec49e` 中纠正。后续处理甲方截图时，应先区分“必须一致的空间骨架”和“可按主题调整的颜色/视觉令牌”，不得用现有页面结构替代甲方明确要求的布局层级。
