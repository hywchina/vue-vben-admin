## `refactor(@rail/web): add extensible design mode catalog`

- 改造动机：甲方提出 CMF、客室零部件、客室效果和报告四类入口；现有设计页按单个应用平铺，继续在页面中硬编码会导致同类能力和多版本变体重复开发。
- 改动范围：新增独立的设计模式目录，集中定义模式名称、说明、提示词占位、图标和有序应用键；新增纯函数，根据后端返回的可见应用与能力契约筛选可用应用。
- 扩展方式：后续新增同类能力或版本时，优先在模式目录追加应用键；页面继续消费平台 API 返回的应用与能力，不引入静态业务结果或旁路执行逻辑。
- 注意事项：报告生成目前只有应用目录记录，没有已发布能力契约；目录允许其未来自动进入可用状态，但当前不得将其展示为已执行成功。
- 验证范围：新增单元测试覆盖四类模式的稳定顺序、不可见应用过滤、缺失能力契约过滤和模式内排序。

## `feat(@rail/web): adapt customer-facing design modes`

- 改造动机：将甲方提出的四类业务入口落到现有设计会话中，同时保持项目、会话、任务、资产与外部执行器的既有真实链路不变。
- 改动范围：在统一输入器下方增加“客室零部件生成、CMF 生成、客室效果生成、报告生成”模式切换；每个模式按目录筛选和排序已发布能力，切换后复用原有草稿保存、参数加载、任务提交和结果流转逻辑。
- 交互适配：模式切换同步更新场景说明和提示词占位；从 URL 或结果流转进入特定应用时自动匹配适用模式；共享应用优先保留当前模式语境。
- 真实性边界：模式是否可用由平台 API 返回的 `visible` 与 `capabilityCode` 共同决定；报告等缺失能力契约的模式显示“待接入”，点击只给出明确说明，不创建任务、不生成静态结果。
- 品牌适配：沉浸式设计页使用合同对应的平台全称；由于甲方材料没有提供可独立使用且已授权的中车 PNG 标识文件，当前继续使用仓库现有标识，避免从截图裁切或自行仿制商标。
- 验证范围：模式目录单元测试扩展到共享能力和专属能力的模式解析；前端 31 项单元测试、目标类型检查、 Oxlint、ESLint 和差异空白检查作为提交前门禁。

## `feat(@rail/web): add multimodal result gallery`

- 改造动机：甲方要求一轮生成多张图片时使用适应数量的网格展示，并在全屏预览中连续查看，避免以技术化结果编号标签反复切换。
- 改动范围：结果卡片在存在多张可预览图片时按两列网格呈现，三张结果使用一大两小布局，四张以上显示四格和 `+N` 聚合；单图和多图均可点击进入全屏预览。
- 公共组件复用：扩展既有图片查看器，增加可选的上一张、下一张按钮及键盘左右方向键；原有缩放、拖拽、滚轮和单图调用保持兼容，资产中心与分区标记预览无需另建实现。
- 结果操作：全屏切换会同步当前结果，下载、保存到资产、继续设计、重新运行和局部重绘继续作用于当前结果；结果头部将“工作流版本”调整为面向用户的“能力版本”，不展示底层工作流名称。
- 验证范围：目标类型检查、Oxlint、ESLint、Stylelint 与差异空白检查通过；多图布局和全屏键盘交互纳入后续真实浏览器验收。

## `feat(@rail/web): align customer design entry points`

- 改造动机：落实甲方对登录首页欢迎区、六个快捷入口、新建设计项目和历史设计续接的要求，同时不削弱现有设计工作台的真实统计与闭环能力。
- 首页入口：新增“开始新设计、查看我的设计、查看资产中心、开始模型训练、开始报告生成、设计工作台”六个快捷入口；新设计使用真实项目创建接口并在成功后进入设计会话，历史设计弹窗使用首页 API 返回的真实最近会话并保留项目切换。
- 服务边界：模型训练和报告生成仅在应用可见且存在已发布能力契约时进入设计页；当前环境缺少契约时明确标记“待接入”，点击不会写入任务或伪造结果。
- 品牌与导航：Web 标题、版权名称、构建默认标题和设计页品牌统一为“客运装备内装模块化分区快速设计平台”；菜单“开始设计”调整为“设计生成”。甲方未提供独立授权 PNG 标识，因此未替换现有标识资源。
- 兼容性：原有设计闭环、统计图表、最近项目、最近任务和成果区域继续保留；快捷入口中的“设计工作台”平滑定位到原闭环区域。
- 验证范围：目标类型检查、Oxlint、ESLint、Stylelint 与差异空白检查通过；项目创建、历史续接、待接入提示和响应式入口布局纳入真实浏览器验收。

## `fix(@rail/web): keep unavailable entries explainable`

- 改造动机：真实浏览器验收发现，给“待接入”入口声明 `aria-disabled` 后，语义化操作与辅助技术会把它视为不可交互，用户无法稳定点击查看未接入原因。
- 改动范围：首页模型训练、报告生成快捷入口和设计页报告模式改用只读 `data-unavailable` 状态标记；视觉待接入样式、文字和真实能力判断保持不变。
- 行为边界：待接入入口仍可触发明确说明，但不会选择应用、创建任务或产生资产；已接入入口继续按原链路导航或切换。
- 验证范围：真实浏览器需复验待接入入口可点击、说明可见、当前模式与 URL 不发生错误切换，并检查控制台错误。

## `fix(@rail/web): enforce current platform identity`

- 改造动机：真实浏览器刷新后页面标题已使用新平台全称，但侧栏仍可能由旧版本偏好缓存恢复旧名称；要求用户清空全部缓存会同时丢失其主题与布局设置。
- 改动范围：偏好初始化完成后仅同步应用名称和版权公司名称两个发布身份字段，现有主题、字号、侧栏、顶栏和快捷键偏好继续保留。
- 注意事项：该同步不读取、不清空浏览器存储，也不改变用户业务数据；平台名称不作为用户可自定义偏好处理。
- 验证范围：真实浏览器刷新后复验文档标题、侧栏品牌与登录布局品牌统一使用当前平台全称。
