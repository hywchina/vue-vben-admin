# 甲方 2026-08-20 修改意见迭代提交记录

本文件按实际提交标题记录本轮迭代。每个提交只处理一项独立目标；提交标题使用英文，以下说明使用中文并记录动机、范围、兼容边界、验证和注意事项。

## docs(project): assess client feedback scope

- 改造动机：甲方意见同时包含可直接实现的交互要求、对现有能力的重复描述、与平台架构冲突的存储建议，以及尚未确定技术路线的训练和报告能力，需要先建立可执行边界。
- 改动范围：新增本轮需求评审、合理性结论、实施范围、暂缓项和验收重点；建立独立中文提交记录。
- 设计取舍：CMF、客室零部件和客室效果作为同一设计会话内的业务上下文，不复制底层工作流；资产继续作为跨能力交换协议；泛化“2D 生 3D”不恢复，仅允许现有多视图 GLB 工作流按真实配置出现。
- 开发注意：训练与报告没有确定外部服务协议，本轮不得增加模拟成功、静态结果或无效提交入口；后续提交必须同步补充本文件。
- 兼容影响：本提交仅新增文档，不改变数据库、API、Web 路由或运行行为。
- 验证记录：已逐页检查原始 Word 的 23 页正文和示意图；压缩包内没有批注部件，主文档 XML 没有插入或删除修订标记；已对照当前代码、迁移和工作流目录核实能力现状。
- 遗留事项：按首页与品牌、设计会话、结果浏览、资产入库目录、测试文档分别提交。

## feat(@rail/web): add client quick start workspace

- 改造动机：原首页以数据概览为主，缺少甲方要求的高频任务入口；用户需要先理解统计图表才能找到新建设计和历史会话。
- 改动范围：首页新增六项快捷入口、新建设计弹窗和跨可访问项目的个人设计会话检索；平台可见名称统一为“客运装备内装模块化分区快速设计平台”。
- 实现细节：“开始新设计”调用真实项目创建 API 并进入设计会话；“查看我的设计”逐项目调用现有会话 API，后端继续按当前用户与项目权限过滤；资产和项目入口使用当前真实路由。
- 状态边界：模型训练和报告生成因外部协议及技术路线未确定，入口显示“待接入”并禁用，不创建任务、不生成静态结果。
- 兼容影响：保留首页原有真实统计、设计闭环、最近会话、任务与成果；未修改数据库、认证、RBAC 或工作流协议。
- 验证记录：提交前执行 Web 类型检查、相关规范检查与单元测试；后续浏览器提交统一验证弹窗、搜索、导航和窄屏布局。
- 注意事项：跨项目会话检索复用每个项目最多 200 条的现有接口；普通用户只能读取自己在有权项目中的未归档会话。

## feat(@rail/web): organize design generation modules

- 改造动机：原设计页按 18 项底层工作流平铺，设计师需要先理解技术能力名称，且沉浸式全屏页隐藏了平台导航、通知、主题与全局助手，不符合甲方提出的整体信息架构。
- 改动范围：设计页重新使用平台固定外壳；会话栏支持收起与展开；新增客室零部件、CMF、客室效果和报告生成四个业务切换项；更新产品名称、默认工作流和输入器交互。
- 实现细节：三个可用业务模块只调整提示词、首批模板和真实应用推荐顺序，任务仍使用原应用目录、能力参数、草稿快照与 Worker；默认能力改为 `text-to-image`，只有真实声明媒体字段的能力显示素材按钮。
- 模板范围：按甲方已明确内容提供颜色、材质、纹样、部件类型、画面角度、客室类型、光环境和窗外环境首批模板；模板只向当前提示词追加可见文本，不绕过工作流参数。
- 状态边界：报告生成保持禁用并显示待接入；多视图三维只作为零部件上下文中的现有真实工作流出现，是否可执行继续由服务端适配器状态决定。
- 兼容影响：不修改 18 份 ComfyUI API JSON、数据库、任务状态机或资产血缘；原有全部应用仍可从“更多”访问。
- 验证记录：新增业务模块排序、报告待接入和模板文本单元测试；执行 Web 类型检查、设计相关单元测试、ESLint 与 Stylelint；后续真实浏览器统一验证壳层高度、会话栏折叠、模块切换、模板和助手。
